1. EXECUTIVE SUMMARY & REAL-WORLD CONTEXT (BEYOND BASIC SIH DESCRIPTION)
================================================================================

While the standard SIH problem statement highlights the heterogeneity of modern
networks and the burden of multi-vendor audits, the reality in production national
critical infrastructure (defense networks, banking backbones, telecom cores,
power grids under NCIIPC/CERT-In mandate) introduces severe constraints that
disqualify 95% of conventional software solutions:

1. THE AIR-GAP MANDATE:
   Defense and critical infrastructure networks run strictly isolated from the
   public internet. Cloud-based LLMs (OpenAI, Claude, Gemini Cloud APIs) are
   strictly forbidden by defense procurement directives because uploading device
   configurations exposes topological secrets, internal IP schemes, ACLs, and
   cryptographic keys to third-party infrastructure.

2. THE "HALLUCINATION IN AUDITING" FATALITY:
   A generative model hallucinating an access control rule or reporting a false
   pass on Telnet/SSH compliance creates a direct cyber exposure. Auditing must be
   100% deterministic, mathematically verifiable, and legally defensible with line-
   level cryptographic proof.

3. THE SYNTACTIC CHURN TRAP:
   Every firmware upgrade (Cisco IOS-XE 17.x, Junos 23.x, FortiOS 7.4, Arista EOS,
   SONiC releases) subtly mutates CLI syntax. Hard-coded regex parsers break
   instantly, while retraining large neural networks requires massive annotated
   datasets that network engineers do not have time to create.

ARGUS SOLVES THIS PARADOX THROUGH A DUAL-ENGINE ARCHITECTURE:
- Engine 1: An authoritative, deterministic rule engine for verified standards.
- Engine 2: A bounded, self-evolving local Machine Learning dialect classifier
  (TF-IDF char/word n-grams + Logistic Regression) that runs 100% offline on any
  standard workstation without GPU or cloud dependency.
- Governance: A strict "Human-in-the-Loop" approval gate ensuring zero silent
  failures and zero unverified automated configuration alterations.

2. ARCHITECTURAL PHILOSOPHY & WHY CONVENTIONAL APPROACHES FAIL
================================================================================

CORE PRINCIPLE:
"Deterministic verification first, bounded local AI second, human sign-off
before learning or change."

WHY REGEX ALONE FAILS:
- Rigid token matching breaks when vendors change keyword order (e.g.,
  `transport input ssh` vs `system services ssh root-login deny` vs `set ssh-admin enable`).
- Zero semantic understanding of negation, hierarchical context blocks, or
  multi-line stanza inheritance (e.g., Junos curly-brace stanzas or Fortinet
  `config system ... edit 1 ... set ... next ... end`).

WHY PURE CLOUD LLMS FAIL:
- Severe data exfiltration risk (leaks enterprise network topology).
- Unpredictable latency and token costs scaling linearly with file sizes.
- Non-reproducible outputs: running the same audit twice can produce different results.
- Zero support for strict corporate air-gaps.

THE ARGUS PARADIGM:
1. Canonical Security Property Model (CSPM):
   Every raw configuration line is normalized into a vendor-neutral intermediate
   representation (AST).
2. Triage & Active Feedback:
   If a line matches a known security property, it audits instantly. If syntax is
   unrecognized, it enters a dedicated Active Learning triage queue where the
   local AI predicts its semantic intent with confidence scoring (0.0 to 1.0).
3. Auditable Knowledge Reversal:
   All learned mappings retain complete provenance (author, timestamp, test vector).
   If a human administrator revokes or corrects a rule, the system calculates the
   exact blast radius across all past device audits and schedules automatic
   re-evaluations.

3. END-TO-END 10-STAGE COMPLIANCE PIPELINE
================================================================================

Stage 1: Multi-Format Ingestion
- Accepts single or bulk upload of `.cfg`, `.conf`, `.txt`, and raw text dumps.
- Automatic file hashing (SHA-256) at ingestion to establish tamper evidence.

Stage 2: Signature-Based Vendor & OS Auto-Detection
- Multi-vector heuristic analysis inspects banner tokens, prompt syntax,
  version signatures, and command paradigms.
- Distinguishes Cisco IOS/IOS-XE, Juniper Junos (hierarchical & flat display set),
  Fortinet FortiOS, Arista EOS, Palo Alto PAN-OS, and Linux/SONiC white-box configs.

Stage 3: Hierarchical & Stanza Context Parsing
- Deconstructs flat stanzas (Cisco `line vty 0 4`), scoped blocks (Fortinet
  `config system admin`), and nested trees (Junos `system { services { ssh; } }`).
- Maintains exact line-number pointers for every token to provide evidentiary proof.

Stage 4: Normalization into Canonical Security Property Model (CSPM)
- Maps proprietary parameters into normalized keys:
  * `mgmt.ssh_only` (Boolean)
  * `mgmt.session_timeout` (Integer seconds)
  * `auth.password_min_length` (Integer characters)
  * `auth.root_login_disabled` (Boolean)
  * `logging.central_syslog` (Array of IP/FQDN endpoints)
  * `time.ntp_servers` (Array of server endpoints)
  * `snmp.v3_encrypted_only` (Boolean)
  * `services.insecure_disabled` (Boolean - Telnet, HTTP, RSH disabled)

Stage 5: Multi-Framework Compliance Logic Engine
- Concurrently evaluates the normalized device model against user-selected benchmarks:
  * CIS Benchmarks (Center for Internet Security Levels 1 & 2)
  * NIST SP 800-53 Rev. 5 (Federal Information Security Modernization Act controls)
  * DISA STIGs (Defense Information Systems Agency Security Technical Implementation Guides)
  * ISO/IEC 27001:2022 (Annex A Technical Controls)
  * NCIIPC Indian Critical Infrastructure Cybersecurity Guidelines

Stage 6: Dialect Intelligence & Unrecognized Syntax Detection
- Any command modifying security-adjacent contexts that fails deterministic parsing
  is extracted into the Unrecognized Syntax Stream.
- Bounded local ML vectorizes the string via Character/Word n-grams (ranges 2-5).
- Logistic Regression model outputs predicted Canonical Property + Confidence Score.

Stage 7: Interactive Human-in-the-Loop Active Learning
- High confidence predictions (>85%) are presented to the administrator with 1-click
  "Accept & Retrain" capability.
- Ambiguous predictions (<85%) provide an intuitive low-code mapping UI allowing
  admins to assign the target property and value extraction rule.
- Zero server restarts or code redeployments required: updates model weights and
  database rules in-memory and on disk (`joblib` + SQLite).

Stage 8: Cross-Vendor Equivalence Graph & Semantic Diffing
- Generates a visual 3-tier node-link graph mapping raw CLI syntax across all
  ingested vendors to the central security property and high-level standard control.
- Provides semantic configuration diffing across devices or between firmware versions.

Stage 9: Counterfactual Security Simulator ("What-If" Engine)
- Allows security administrators to select remediation controls in a risk-free sandbox.
- Instantly calculates the projected compliance score lift (e.g. 12.5% -> 87.5%).
- Synthesizes vendor-native CLI commands with exact copy-paste hardening scripts
  customized for that specific device's OS.

Stage 10: Executive & Technical Audit Reporting
- Generates comprehensive compliance audit reports with:
  * Executive pass/fail summary & risk distribution radar charts
  * Line-by-line evidentiary audit logs linking each control to exact config lines
  * Tailored CLI remediation playbooks
  * Cryptographic SHA-256 verification seal guaranteeing audit integrity for compliance officers

4. THE 5 FLAGSHIP INNOVATIONS / PRD DIFFERENTIATORS
================================================================================

--------------------------------------------------------------------------------
DIF-01: SELF-EVOLVING VENDOR DIALECT ENGINE (LOCAL ML CLASSIFIER)
--------------------------------------------------------------------------------
- PROBLEM: Network equipment manufacturers invent proprietary keywords with each
  firmware release. Static tools fail silently; cloud LLMs leak confidential topology.
- OUR INNOVATION:
  * Built an embedded machine learning pipeline using Scikit-Learn.
  * Feature Extraction: Combined character n-grams (2-5) and word n-grams with TF-IDF
    vectorization. This catches sub-word semantics (e.g., `ssh-admin`, `sshd`,
    `crypto_ssh`, `transport_ssh`).
  * Classifier: Regularized Multiclass Logistic Regression trained on diverse network
    dialects.
  * Inference Speed: Sub-millisecond (0.4ms per command), running completely offline.
  * Training Loop: Incremental retrain upon human validation without rebuilding the app.

--------------------------------------------------------------------------------
DIF-02: UNIVERSAL SECURITY INTENT COMPILER
--------------------------------------------------------------------------------
- PROBLEM: CIS and NIST guidelines are written in human language, but network
  devices understand only vendor CLI commands. Network engineers struggle to
  translate high-level policy into enforceable checks across 15 different vendors.
- OUR INNOVATION:
  * Natural Language Intent Compiler transforms freeform administrative policy statements
    into an Abstract Syntax Tree (AST).
  * Example Input: "Management access must enforce SSH-only and central syslog must be active."
  * Compiler Output: AST Predicates:
    `AND(EQUALS(mgmt.ssh_only, true), NOT_EMPTY(logging.central_syslog))`
  * Execution: Evaluates instantaneously across the entire multi-vendor fleet in one pass.

--------------------------------------------------------------------------------
DIF-03: CROSS-VENDOR EQUIVALENCE GRAPH
--------------------------------------------------------------------------------
- PROBLEM: Security leadership cannot easily verify if Cisco, Juniper, and Fortinet
  firewalls are implementing the exact same logical defense control.
- OUR INNOVATION:
  * A 3-Tier Convergent Graph Model:
    [Tier 1: Vendor Concrete Syntax]
       Cisco: `transport input ssh`
       Juniper: `set system services ssh`
       Fortinet: `set admin-ssh-access enable`
              ↓ (Converges to)
    [Tier 2: Canonical Security Property]
       `mgmt.ssh_only = TRUE`
              ↓ (Maps to)
    [Tier 3: Regulatory Standard Controls]
       CIS 4.1 | NIST SP 800-53 AC-17 | DISA STIG NET0410 | ISO 27001 A.9.4.2
  * Visual interactive node-link exploration in the GUI with full search & filter.

--------------------------------------------------------------------------------
DIF-04: COUNTERFACTUAL SECURITY SIMULATOR ("WHAT-IF" SANDBOX)
--------------------------------------------------------------------------------
- PROBLEM: Applying network hardening blindly can take down production systems or
  lock administrators out of remote management.
- OUR INNOVATION:
  * In-memory dry-run sandbox that simulates state transitions.
  * The administrator toggles individual remediations (e.g., "Enforce Session Timeout",
    "Rotate to SNMPv3") on a failed device.
  * Real-Time Feedback:
    - Calculates projected compliance score gain before touching production hardware.
    - Synthesizes the exact vendor-specific CLI configuration delta required.
    - Warns of operational lockout risks (e.g., disabling Telnet before SSH key generation).

--------------------------------------------------------------------------------
DIF-05: AUDITABLE LEARNING & KNOWLEDGE REVERSAL (BLAST-RADIUS GOVERNANCE)
--------------------------------------------------------------------------------
- PROBLEM: If an administrator accidentally approves an incorrect ML dialect mapping,
  traditional AI systems suffer from "data poisoning" that silently corrupts all
  subsequent audits.
- OUR INNOVATION:
  * Immutable Knowledge Registry tracks complete provenance: author, timestamp,
    target property, training sample, and audit dependencies.
  * 1-Click Revocation: If a mapping is revoked, the Knowledge Reversal Engine
    performs automatic Blast-Radius Impact Analysis across the database.
  * Automatically flags every historical audit report that relied on the revoked rule
    and queues them for automated re-evaluation.

BACKEND MODULES (FastAPI, Python 3.10+, SQLite, Scikit-learn):
--------------------------------------------------------------------------------
1. `backend/parser.py`:
   - High-throughput multi-vendor tokenizer & AST generator.
   - Cisco IOS/IOS-XE parser with stanza scoping (`line vty`, `interface`, `aaa`).
   - Juniper Junos parser supporting both hierarchical block braces `{ ... }` and flat `display set`.
   - Fortinet FortiOS parser handling `config ... edit ... set ... next ... end` recursion.
   - Line-number evidentiary indexer mapping every parsed property to exact raw line numbers.

2. `backend/compliance.py`:
   - Multi-standard evaluation engine executing against CIS Benchmarks, NIST SP 800-53,
     DISA STIGs, ISO/IEC 27001, and NCIIPC.
   - Computes weighted compliance scores, critical severity breakdowns, and pass/fail/partial verdicts.

   - Scikit-learn TF-IDF + Logistic Regression dialect learning pipeline.
   - Char/Word n-gram vectorizer (ngram_range 2-5).
   - Dynamic retraining API with local `.joblib` model serialization.
   - High-confidence candidate suggestion and low-confidence quarantine triage.

4. `backend/intent_compiler.py`:
   - Natural language tokenizer, slot filler, and AST compiler.
   - Boolean logic evaluator (`AND`, `OR`, `NOT`, `EQUALS`, `CONTAINS`, `GREATER_THAN`).
   - Fleet-wide cross-device evaluation with matching/failing device lists.

5. `backend/simulator.py`:
   - In-memory state transition and counterfactual delta analyzer.
   - Vendor CLI hardening script synthesis for Cisco, Juniper, Fortinet, and Arista.
   - Step-by-step remediation plan generator with rollback scripts.

6. `backend/knowledge.py`:
   - Knowledge registry management with full provenance logging.
   - Blast-radius calculation engine tracing audit report dependencies.
   - Automated cascade re-audit scheduler upon rule revocation.

7. `backend/semantic_diff.py`:
   - Cross-device and cross-version semantic configuration differential engine.

8. `backend/report.py`:
   - Tamper-evident executive & technical HTML/PDF report generator.

9. `backend/database.py`:
   - SQLite persistence layer with relational schema:

10. `backend/main.py`:

DEFENSE STRATEGY FOR TOUGH JURY QUESTIONS:
--------------------------------------------------------------------------------

Q1: "Why did you build a local ML model instead of using Llama-3 or GPT-4?"
A1: "In defense, banking, and critical infrastructure, sending device configurations
     to a cloud API violates strict data classification laws because configs contain
     internal IP architectures, ACLs, and secrets. Furthermore, running local 70B
     LLMs requires expensive enterprise GPUs that field auditors do not have on their
     laptops. Our Scikit-Learn TF-IDF char/word n-gram classifier runs in 0.4 milliseconds
     on any standard CPU, requires zero internet connection, and provides explainable
     confidence scores without generative hallucinations."

Q2: "What happens if an admin incorrectly approves a dialect mapping?"
A2: "In traditional machine learning, bad human feedback poisons the dataset permanently.
     In ARGUS, we engineered Feature DIF-05: Auditable Knowledge Reversal. Every learned
     rule maintains cryptographic provenance and an audit dependency graph. When an
     admin revokes a rule, ARGUS calculates the exact blast-radius, identifies every
     audit that relied on the poisoned mapping, and flags them for automated re-audit."

Q3: "How does ARGUS support new vendors without redeploying code?"
A3: "Through our Active Learning Loop. When an unknown command appears, the dialect
     engine classifies it into our Canonical Security Property Model. Once the admin
     confirms the mapping in our GUI, the rule is stored in our persistent database
     and updates the in-memory classifier weights immediately. The parser now recognizes
     that vendor dialect permanently across all future uploads without writing a single
     line of code or restarting the server."

Q4: "Can an administrator accidentally lock themselves out with your remediation scripts?"
A4: "That is precisely why we engineered the Counterfactual Security Simulator (DIF-04).
     Before any CLI command is applied to production hardware, the administrator runs a
     counterfactual dry-run in ARGUS. The simulator detects dependency conflicts—such as
     disabling Telnet before verifying SSH key generation—and warns the admin before
     synthesizing the final copy-paste configuration script."
